tl;dr

shieldbreak takes a saved memory dump of ssh-agent and gets an unencrypted private key from it. The method is Piergiovanni Cipolloni's from 2021. What I did was take his live-process procedure and turn it into an offline tool that runs in Docker.

I wrote this because I forgot the passphrase to one of my own SSH keys. The key was still loaded in ssh-agent, which keeps it in memory in a shielded form, so instead of rotating it everywhere I dumped the agent's memory and pulled the key.

What shielding is

When you run ssh-add, the agent does not keep the key sitting in plaintext. Since OpenSSH 8.0 it shields it. It generates a random 16 KB prekey, hashes that down to a symmetric key, and encrypts the private key with it for security reasons.

That covers a partial read. It does nothing against someone who can read agent's memory in full, because then they have the prekey sitting right next to the ciphertext. Anyone who can take one already has the access needed to compromise the agent.

Whose technique this is

The method is not mine. Piergiovanni Cipolloni of HN Security wrote it up in July 2021, including the sshkey struct layout and the use of sshkey_unshield_private() to rebuild the key. Read his article first. This is a reimplementation of what he described, and the actual unshield still leans on the function he identified.

How it works

There are two steps. First a small Go program reads the dump. It walks the ELF segments, finds the sshkey struct, and writes out two files: the shielded key blob and the 16 KB prekey.

Then a gdb script loads a debug build of ssh-keygen, rebuilds a ssh key from those two files, calls sshkey_unshield_private(), and saves the plaintext key. That last step is unchanged from the original.

Note: The struct offsets are specific to one OpenSSH build on x86_64. A different build can lay the struct out differently, so the offsets in ssh_key_reader.go may have to be updated in the future.

Running it

Everything is in a container, so you do not need a matching OpenSSH build on your machine. The repo ships a generator that makes a real ssh-agent dump to test with, and the e2e test recovers a key and checks it against the original by fingerprint.

The code is on GitHub under MIT, with the parser, the gdb script, the Docker build and the tests. If your own key is still loaded in an agent, this is the best way to get it back without the passphrase.
